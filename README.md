## Самый простой вариант: полный ZIP с зависимостями

1. Откройте **GitHub → Actions → «Проверка лабораторных работ» → последний успешный запуск**.
2. Внизу страницы скачайте архив **`Laravel9_SQLite_готовый_проект`** — в нём есть папка `vendor/` с установленными зависимостями. Это проще, чем скачивать обычный ZIP исходников через кнопку Code.
3. Распакуйте папку сайта. Установите PHP **8.0.2 или новее** с расширениями `pdo_sqlite`, `mbstring`, `openssl`, `fileinfo` (например, из XAMPP). 
4. На macOS запустите `START_MAC.command` (если система блокирует двойной щелчок — в Терминале выполните `bash START_MAC.command`). На Windows запустите `START_WINDOWS.bat`.
5. Откройте сайт по адресу **http://127.0.0.1:8000**. Пока работает сайт, окно терминала закрывать не нужно. Остановка — `Ctrl+C`.

При первом запуске скрипт **сам создаёт `.env`, случайный `APP_KEY`, файл SQLite `database/database.sqlite`, таблицы и 12 учебных статей**. Создаётся локальный модератор со случайным паролем. Его адрес и пароль сохраняются **только на вашем компьютере** в `LOCAL_LOGIN.txt` (файл игнорируется Git). Повторный запуск не удаляет статьи и комментарии.

Если вы скачали исходники через кнопку **Code → Download ZIP**, папки `vendor` в них нет. Для такого варианта необходим Composer:
```bash
composer install
php scripts/setup-local.php
php artisan serve --host=127.0.0.1 --port=8000
```
Если Composer блокирует установку из-за предупреждений безопасности устаревшего Laravel 9, предпочтительнее готовый ZIP из Actions.

## Лабораторная работа №1. Создание макета страниц сайта

Сделала общий шаблон сайта на Blade с шапкой, меню и подвалом. Добавила главную страницу, страницы «О нас» и «Контакты». Контакты передаются в шаблон из массива через `view()`.

## Лабораторная работа №2. Вывод данных из JSON-файла

Создала контроллер `MainController` с методом `index()`. Контроллер читает файл `public/articles.json` и передаёт массив статей на главную страницу. Карточки формируются через Blade: отображаются названия, даты, описания и изображения из полей `name`, `date`, `shortDesc`, `preview_image`.

При нажатии на `preview_image` открывается страница `galery` с полным изображением `full_image` и текстом статьи. Если в JSON отсутствует `shortDesc`, на главной отображается поле `desc`. Используются исходные данные и изображения из задания.


## Лабораторная работа №3. Регистрация пользователей

Создала страницу регистрации `resources/views/auth/signin.blade.php` с полями «Имя», «Email» и «Пароль». Добавила CSRF-токен (`@csrf`) и отправку данных методом POST на `/signin`.

В `AuthController` реализовала методы `create()` и `registration()`. Первый открывает форму, второй проверяет данные с помощью Laravel `Request::validate()` и возвращает JSON-ответ. Для имени установила обязательное заполнение и ограничение до 80 символов, для почты — проверку формата email, для пароля — длину от 8 до 72 символов. В целях безопасности пароль в ответе скрывается. В этой лабораторной данные не сохраняются.

Добавила ссылку «Регистрация» в основное меню. На главной странице указала своё имя, а на странице «О нас» обновила формулировку про лабораторные работы №1–9.

## Лабораторная работа №4. Работа со статьями в базе данных

Создала модель `Article` с полями заголовка, краткого описания, полного текста, даты публикации и статуса. Миграция `create_articles_table` создаёт таблицу `articles` в базе данных.

Добавила `ArticleFactory`, которая с помощью Faker генерирует тестовые статьи. В `DatabaseSeeder` вызывается фабрика для создания 12 записей. Контроллер `NewsController` получает опубликованные статьи из базы, сортирует по дате и передаёт их в Blade-представление `news.index`. На странице новостей отображается список, а по ссылке открывается полный текст статьи.

Для проверки работы миграции и фабрики использовала команды `php artisan migrate:fresh --seed` и `php artisan test`. Добавила тесты модели, заполнения базы, списка и отдельных статей. Для SQLite сначала создаётся пустой файл `database/database.sqlite`.

## Лабораторная работа №5. Пагинация и CRUD

Добавила постраничный вывод опубликованных новостей (по 6 записей) и страницу управления `/management` (по 8 записей). В `NewsController` реализованы создание, просмотр, изменение и удаление статей. ## Лабораторная работа №6. Авторизация и аутентификация

Добавила регистрацию с сохранением пользователей в таблицу `users`, проверкой полей и хешированием пароля. После регистрации происходит переход на страницу входа. При входе Laravel создаёт сессию и токен Sanctum, при выходе токен удаляется, сессия аннулируется, а CSRF-токен обновляется.

- `UserSessionController` — регистрация, авторизация и выход.
- `users` — таблица пользователей, `personal_access_tokens` — таблица Sanctum.
- `auth/register.blade.php` и `auth/login.blade.php` — формы с `@csrf`.
- `auth:sanctum` — защита управления статьями и CRUD-маршрутов.
- `/signin` — учебная форма из лабораторной №3 с JSON-ответом.
- `tests/Feature/AuthSanctumTest.php` — тесты регистрации, входа, токенов и защиты маршрутов.

## Лабораторная работа №7. Роли, политики и шлюзы

Добавила две роли — модератор и читатель. Таблицы `roles`, `users`, `comments` связаны через Eloquent. `RoleSeeder` создаёт роли, `ModeratorSeeder` добавляет модератора, а новые зарегистрированные пользователи становятся читателями.

Для статей настроила `ArticlePolicy`, для комментариев — `CommentPolicy`. Хук `Gate::before` разрешает модератору действия до остальных проверок, шлюз `manage-comments` управляет доступом к модерации. Читатели просматривают опубликованные статьи и оставляют комментарии. Модератор создаёт, редактирует и удаляет статьи; комментарии только принимает или отклоняет, не меняя чужой текст. Для отказа в доступе показывается страница 403 с понятным сообщением.

Перед первым наполнением базы можно указать `MODERATOR_EMAIL` и `MODERATOR_PASSWORD` в `.env`. Если пароль не задан, при первом создании модератора генерируется случайный пароль, который не сохраняется в репозитории. Чтобы задать свой пароль существующему модератору, нужно заполнить `MODERATOR_PASSWORD` и повторно вызвать `php artisan db:seed --class=ModeratorSeeder`.

## Лабораторная работа №8. E-mail уведомления модератору

После создания новости отправляю уведомление модераторам через `Mail::to(...)->send()`. Класс `ArticleCreatedMail` получает объект статьи и формирует тему и содержимое письма в методе `build()`. HTML-шаблон расположен в `resources/views/emails/article-created.blade.php`.

SMTP-параметры берутся из `.env`, конфигурация транспорта находится в `config/mail.php`. Пароль почтового приложения не включён в репозиторий. Для проверки отправки используется `Mail::fake()` — тесты проверяют получателей и содержимое, не отправляя реальные письма.

**Основные файлы:** `app/Mail/ArticleCreatedMail.php`, `resources/views/emails/article-created.blade.php`, `config/mail.php`, `app/Http/Controllers/NewsController.php`, `tests/Feature/ArticleMailTest.php`.


## Лабораторная работа №9. Модерация комментариев

Добавила поле `is_approved` с начальным значением `false` в таблицу `comments` через отдельную миграцию. Уже опубликованные комментарии при обновлении базы сохраняют статус одобренных.

Новый комментарий записывается в базу и ожидает модерации. После отправки показывается сообщение об ожидании проверки, а на странице статьи выводятся только одобренные комментарии. В профиле `/account` автор видит статус собственных комментариев («На модерации» или «Опубликован») и уведомления о решениях модератора; списки комментариев и уведомлений имеют независимую пагинацию.

Модератору доступна страница `/moderation` со списком комментариев на проверке. Здесь можно принять комментарий (он появится под статьёй) или отклонить (комментарий будет удалён). Маршруты защищены `auth:sanctum` и шлюзом `manage-comments`, формы используют CSRF.

**Основные файлы:** `database/migrations/2026_11_19_000002_add_is_approved_to_comments_table.php`, `CommentController`, `NewsController`, `resources/views/comments/moderation.blade.php`, `tests/Feature/CommentModerationTest.php`.
